# 小记 · 灵感 / 倒计时 / 待办

一个单文件的网页应用：三个标签页，装灵感、装倒计时、装待办。
数据全部存在使用者自己的设备里（浏览器 localStorage），不上传任何服务器。

- **在线地址**：https://lix12676-web.github.io/time-up/
- **本地文件**：`index.html`（双击即可打开，无需装任何东西）
- **当前版本**：v2.0.0（2026-11-18）

---

## 一、这个应用干什么

| 板块 | 用来记什么 | 每条卡片上有什么 |
|---|---|---|
| 灵感 | 随手想到的一句话、一个点子 | 内容、记录时间、改、删 |
| 倒计时 | 有明确日子的事（考四级、交论文、体检） | 名字、目标日期、**还剩几天**、进度条、改、删 |
| 待办 | 要做但没有具体日子的事 | 内容、未完成/已完成、勾选、删 |

时间轴上的"还剩几天"是**实时算的**：改了系统日期或过了一天，重新打开就自动变，不需要手动维护。

---

## 二、怎么用（使用者视角）

1. 手机 Chrome 打开在线地址 → 右上 ⋮ → **安装应用**，桌面会出现独立图标，点开全屏、没有地址栏。
2. 打开后默认在"灵感"页，直接写，**回车就保存**（Shift + 回车才是换行）。
3. 切到"倒计时"，写名字 + 选日期 + 点"加上"，卡片立刻显示还剩多少天。
4. 切到"待办"，写一句就能加，点 ✓ 变已完成，会沉到列表后面。
5. 换手机：底部"备份 / 导出 / 换设备" → 导出备份（JSON）→ 新设备点导入，选那个文件。

```

├── manifest.json   ← PWA 清单：应用名、图标、全屏方式
```

## 四、数据结构（localStorage）

存储 key：`shige.v2`

```json
{
  "tab": "idea | count | todo",
  "ideas":  [ { "id": 1700000000000, "text": "一句话灵感", "ts": 1700000000000 } ],
  "counts": [ { "id": 1700000000000, "title": "考四级", "date": "2026-12-12",
               "created": "2026-11-18", "ts": 1700000000000 } ],
  "todos":  [ { "id": 1700000000000, "text": "交作业", "done": false, "ts": 1700000000000 } ]
}
```

字段说明：

- `id`：毫秒时间戳，同时当唯一键用。
- `ts`：创建时间（毫秒），用于排序和卡片上显示"11月18日 19:12"。
- `counts[].date`：目标日期，格式必须是 `YYYY-MM-DD`；`created` 是创建那天，用来算进度条百分比。
- 旧版本（time-up v1，key = `timeup.v2`）的待办会在首次加载时自动迁移过来。

**改数据结构时必须同时改三处**：`load()` 的兜底、`renderXxx()` 的读取、导出/导入的分支。

## 五、想改东西，改哪一段

`index.html` 里所有逻辑都在一个 `<script>` 里，按注释分隔成块，搜这些关键词就能定位：

| 想改什么 | 搜这个 | 说明 |
|---|---|---|
| 存哪个 key（版本换名） | `var KEY = 'shige.v2'` | 改名等于清空旧数据，谨慎 |
| 顶部日期时间格式 | `function tick()` | 现在是"2026年11月18日 星期三 19:12" |
| 灵感卡片长什么样 | `function renderIdeas()` | 卡片 HTML 模板 |
| 倒计时怎么算天数 | `function renderCounts()` 里的 `daysBetween` | 按自然日算，不看时分 |
| 待办排序 | `function renderTodos()` | 未完成在前，已完成在后 |
| 三个板块的颜色 | `<style>` 顶部 `:root` 的 `--idea` `--count` `--todo` | 卡片左侧色条、倒计时数字都用它 |
| 加/删/改的确认弹窗 | `function onCardClick()` | 删除有 `confirm` 二次确认 |
| 导出的 CSV 列 | `exCsv` 的 `onclick` | 五列：类型、内容、日期、状态、创建时间 |
| 首次打开预置的示例 | 启动段 `if(DB.counts.length===0 ...)` | 目前预置一条"考四级 2026-12-12"，可删掉这段 |

## 七、部署

这仓库开了 GitHub Pages，分支 `main`、根目录。

- 改 `index.html` → 提交到 `main` → 等 1 分钟左右，Pages 自动重新构建。
- 注意：`sw.js` 有缓存，改完页面后**手机上可能要下拉刷新一次**或关掉重开才会更新；如果彻底不更新，把 `sw.js` 里的 `CACHE = 'timeup-v1'` 改成 `v2` 之类的版本名。

## 九、已知限制（别当成 bug）

1. **不能主动推送通知**。网页关掉后不会弹提醒；真要提醒得靠外部定时任务。PWA 加通知权限在 Android 可行、iOS 基本不行。
2. **数据只在本机**。换设备、换浏览器、清缓存都会丢，必须靠导出/导入。
3. **没有云同步**。要多人或多设备实时同步，得加后端账号系统，那是另一个量级的工程。
4. **没有安装包（APK）**。这是 PWA，靠浏览器"安装应用"生成桌面图标；要 APK 需要 Android 构建环境另外打包。
5. 日期一律按"自然日"算，不精确到时分。

## 十、给接手的人 / 另一个 AI 的提示

1. 先读这份 README 的第四、第五节，再看 `index.html` 的 `<script>`，结构是：数据层 → 渲染层 → 事件层 → 导入导出 → 启动。
2. 修改前先备份：把 `index.html` 复制成 `index-vX.html` 放同目录（不会被 Pages 影响，只是留档）。
3. 改动渲染函数后，务必核对 **空列表状态**（`.empty` 那段）和**已完成/已过期状态**，这两个最容易漏。
4. 任何时候不要改动 `KEY = 'shige.v2'` 除非有意清空用户数据；要升级结构就写迁移逻辑，像现在迁移 `timeup.v2` 那样。
5. 卡片模板里所有用户输入都必须过 `esc()`，防止 HTML 注入。
6. 手机端点击区不小于 44px，现在标签页和按钮按这个尺寸做的，别改小。
